2014 CSAW CTF WriteUp

📝 赛事概况

  • CSAW CTF 2014 是第 11 届 “网络安全意识周” 的核心赛事，由纽约大学理工学院（NYU-Poly） 主办。比赛的核心目标是为全球的本科生提供一个接近真实攻防环境的入门与进阶平台。虽然预选赛面向全球开放，但最终晋级线下决赛的资格仅限于美国与加拿大的学生队伍

Web

pps（任意文件读取 + PHP 弱比较 + switch 贯穿执行）

程序随后显示菜单

第一步：利用文件读取泄露 PHP 源码

这里的逻辑是：

  1. 用户输入一个文件路径或 URL

  2. 使用 str_replace() 删除其中的 file 和 flag 字符串

  3. 如果发生替换，就拒绝访问

  4. 使用 fopen() 打开指定文件

  5. 将读取到的内容放入 $puns 数组

fopen() 不仅可以读取 URL，也可以读取本地文件，所以我们可以直接读取当前目录下的 pps.php

第一次交互输入

第二步：分析隐藏的管理员密码

通过源码泄露，我们发现了选项 5

preg_replace("/[1-9]/", "", $password); 只删除了数字 1～9，但是没有删除数字 0、字母、十六进制前缀 0x

因此，我们需要寻找一种输入方式，使其通过过滤，同时在后面的密码比较中仍然能够匹配正确的密码

if ($password != "180019117") 使用的是弱比较

我们知道 0xabadfad 是 180019117，在题目使用的 PHP 5 环境中，两个字符串会被识别为相同的数值：180019117 == 180019117

这样就绕过成功了

第三步：利用 switch 穿透加载 Flag 文件

密码验证成功后，程序会要求输入：Please enter the new file name:

观察后面的代码：$punsource = preg_replace("/[^a-zA-Z]/", "", trim(fgets(STDIN)));

这个正则表达式的作用是只保留英文字母，但是这里还有一个更关键的细节，case 5 后面没有 break

因此，当管理员密码验证成功时，程序不会停在选项 5，而是继续执行选项 6

这就是 PHP switch 中的 Fall-through（贯穿执行）

所以我们输入 flag 会直接读取 Flag 文件保存到 $puns 数组，最后只需要重新选择 2 即可拿到 flag

webroot（AMF 协议篡改 + DES_ECB + SQLite SQL 注入）

这道题比较有意思，它不是普通的 SQL 注入，而是将 AMF 协议篡改、DES_ECB 加密、SQLite SQL 注入、数据库文件写入组合在一起的一道 Web 综合题

首先要理解这道题的请求流程，网站并不是简单地通过 HTTP 表单提交数据，而是使用 AMF 协议与 PHP 后端进行通信

AMF 全称：Action Message Format，它是 Adobe Flash 生态中使用的一种二进制序列化协议

在这道题中，客户端通过 AMFPHP 调用服务器端的方法，其中一个关键方法是：saveHaiku

可以将整个应用理解为：

这里有一个关键点，我们不能只在浏览器中修改普通表单参数，因为实际传输的是 AMF 二进制数据

因此，需要先理解 AMF 数据包的结构，再寻找参数中的漏洞

第一处漏洞：timestamp 参数 SQL 注入

它有一个特殊要求是必须修改 AMF 数据包中 timestamp 参数的类型，从 Number 变成 String

正常情况下，客户端将 timestamp 作为 Number 发送，后端反序列化后得到的是数值类型，程序可能按照数字处理

但是当我们把 AMF 中的 Number 改成 String 后，后端得到的就是字符串；如果后端将该参数直接拼接到 SQL 语句中，而没有进行参数化查询，就可能将原本的数据内容解释成 SQL 语法

数据类型 类型标记 数据结构
Number 0x00 1 字节标记 + 8 字节 Double
String 0x02 1 字节标记 + 2 字节长度 + 字符串

第二处漏洞：encrypted haiku 参数 SQL 注入

haiku 参数经过 DES_ECB 加密，想要在这个参数中注入 SQL，需要先恢复 DES 密钥，再对恶意明文进行加密

我们可以利用题目中较弱的密钥生成或密钥空间，对候选密钥进行枚举

基本流程：

  1. 获取一组正常的明文 Haiku

  2. 获取对应的加密后 Haiku

  3. 形成已知明文和密文对

  4. 根据题目源码确定密钥生成规则和候选范围

  5. 枚举候选密钥

  6. 使用 DES_ECB 解密密文

  7. 检查结果是否与已知明文一致

  8. 确认正确密钥

第三步：利用 SQLite ATTACH DATABASE 写入文件

SQLite 允许通过 SQL 语句附加其他数据库

作用是将一个数据库文件加载到当前 SQLite 连接中，如果指定的文件不存在，SQLite 可以创建新的数据库文件

执行后，服务器文件系统中会出现 /tmp/test.db

这里存在一个重要问题：SQLite 创建的文件并不是普通文本文件，而是 SQLite 数据库文

那么，为什么可以用它生成 PHP 文件？

关键是 PHP 文件的解析机制：PHP 文件不要求文件的所有内容都是 PHP 代码，例如

PHP 解释器会：

  1. 将 PHP 标签之前的内容当作普通输出

  2. 遇到 <?php 后开始解析 PHP 代码

  3. 遇到 ?> 后结束 PHP 代码解析

所以，即使一个文件前面存在其他二进制内容，只要后面包含合法的 PHP 起始标签，PHP 仍然可能执行其中的代码

return_of_the_wieners（AVR 固件——ATmega168 芯片）

Intel HEX 是一种以文本形式保存二进制数据的文件格式，常见于单片机固件烧录，打开文件可以看到：

每一行都是一条 Intel HEX 记录，其基本结构：

字段 含义
LL 数据长度
AAAA 数据存放地址
TT 记录类型
DD 实际数据
CC 校验和

例如 :100000000C945C000C9479000C9479000C947900A9，可以拆成

这说明我们需要先将 Intel HEX 转换为内存映射，再进行 AVR 汇编分析

可以使用 Python 自己解析，也可以使用现成工具：pip install intelhex

如何判断出是 AVR 固件的呢？

看重复模式，认出中断向量表

每个向量占 4 字节，内容几乎全部相同 → 这是典型的 MCU 中断向量表

把 0C 94 按小端读成 0x940C，查指令表：

不同 AVR 芯片的 Flash 大小：

芯片 Flash
ATtiny 1–8 KB
ATmega8 8 KB
ATmega168 16 KB
ATmega328 32 KB

上面的导出的固件大小刚好是 16 KB，所以确定是 ATmega168 芯片

IDA 反编译先选择 AVR 处理器架构，再选择列表中的 ATmega168P

jmp loc_1583 跳转到 pinMode 实现代码

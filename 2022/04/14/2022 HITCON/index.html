2022 HITCON WriteUp

HITCON CTF 是由台湾的 HITCON 安全社区组织并主办的国际性网络安全夺旗竞赛，与每年的 HITCON 台湾骇客年会同期举办

🏆 赛事概况

  • 比赛时间：2022 年 11 月 25 日 21:00 至 11 月 27 日 21:00 (UTC+7)

  • 比赛形式：线上 Jeopardy（解题） 模式

  • 赛事规模：共吸引了来自全球 95 个国家的 1,243 支队伍参赛

  • 题目设置：共 27 道挑战题，涵盖 Web、Pwn、Crypto、Reverse、Misc 等方向

Misc

lemminx（XXE 无回显绕过）

题目描述：Eclipse LemMinX XML Language Server，版本 0.19.1

LemMinX 是 Eclipse 基金会开源的一个 XML 语言服务器。当你在 VSCode 中打开一个 .xml 文件时，编辑器需要知道：

  • 这段 XML 语法对不对？

  • 光标放在某个标签上时，应该提示什么补全？

  • 这个标签的定义在哪里？

这些功能不是 VSCode 自己实现的，而是 VSCode 通过 LSP 协议 向 LemMinX 这个 “后端服务” 请求的。LemMinX 接收请求，分析 XML，然后把结果返回给编辑器

LemMinX 是一个网络服务，它通过标准输入/输出或 TCP 接收 LSP 消息，解析 XML 文档，并返回诊断信息。它本身不面向最终用户，而是面向编辑器（客户端）

LSP 的消息格式类似 HTTP，由 Header 和 Body 两部分组成，中间用 \r\n\r\n 分隔

Body 是一个标准的 JSON-RPC 2.0 消息：

连接服务后，第一件事是发送 initialize 请求，告诉服务器 “我是什么编辑器，我支持什么功能”

  • capabilities 告诉客户端 “我能做什么”

  • textDocumentSync: 2 表示支持增量文档同步（Full 是 1，Incremental 是 2）

  • completionProvider 表示支持自动补全

  • serverInfo.version: "0.19.1" 确认了版本号

初始化完成后，客户端需要发送 initialized 通知

initialize 是握手请求，服务端回复能力列表后，客户端再发 initialized 确认 “我收到了，你可以开始工作了”

通过 textDocument/didOpen 通知发送一个恶意的 XML 文档

diagnostics 是空数组。没有报错，但也没有返回文件内容

原因一：LemMinX 在 0.19.1 版本中已经默认禁用了外部实体的解析

原因二：即使 XXE 成功读取了文件，LemMinX 也不会把解析结果返回给客户端。LemMinX 的工作方式是：解析 XML → 分析语法 → 返回诊断信息（比如 “第 3 行缺少闭合标签”）

原因三：publishDiagnostics 返回的是语法层面的诊断（如缺少标签、属性值无效等），不会包含实体展开后的内容。即使 /flag 被读取了，你也不可能从诊断信息中看到它

既然 XML 解析层面走不通，我们把注意力转向 LemMinX 的配置系统

LSP 协议规定，客户端在 initialize 请求中可以通过 initializationOptions 字段传递配置参数。很多语言服务器会读取这个字段来调整自己的行为——比如设置日志路径、配置代码格式化规则、指定 Schema 文件位置等

核心问题：LemMinX 的 initializationOptions 支持哪些配置？有没有可以写入任意文件的配置项？

CVE-2026-94108

漏洞源码位于 getid3-1.9.26/getid3/getid3.lib.php

LIBXML_NOENT 启用了实体替换——这是 XXE 的前提

关键：

  • libxml_disable_entity_loader(false) —— 允许加载外部实体

  • simplexml_load_string 用 GETID3_LIBXML_OPTIONS 传入，包含 LIBXML_NOENT

  • 传入的 $XMLstring 来自 WAV 文件的 iXML chunk

结论：XML2array 对攻击者可控的 XML 字符串进行解析，存在 XXE 漏洞

只要上传的 WAV 文件里有 iXML chunk，其内容就会进入 XML2array，触发 XXE

UTF-16BE 编码绕过

WAF 用 stripos($rawBytes, '<!DOCTYPE') 在原始字节流中搜索。stripos 把 needle 当作 UTF-8/ASCII 字节序列处理

UTF-16BE 编码的 <!DOCTYPE：

每个 ASCII 字符前插入了 0x00 空字节，stripos 搜索的字节序列是 3C 21 44 ...（9 字节），而 UTF-16BE 里是 00 3C 00 21 ...（18 字节），逐字节匹配失败

XML 规范规定，遇到 BOM FE FF 时切换到 UTF-16BE 解码器。解析器会把 00 3C 00 21 ... 还原为 <!DOCTYPE，正常解析，只有 BOM + 编码内容都正确，libxml 才会识别

libxml 2.9.x 的一个重要限制：在解析外部 DTD 时，libxml 拒绝执行其中的 “通用实体定义”，只处理参数实体

libxml 的行为：

  • 解析 evil.dtd 时，%eval 展开生成的 <!ENTITY % exfil SYSTEM ...> 被静默忽略

  • %exfil; 引用时找不到实体，不发起 HTTP 请求

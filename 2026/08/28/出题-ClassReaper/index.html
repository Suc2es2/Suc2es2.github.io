出题——ClassReaper

前言

这次出题主要考察 RTTI 恢复以及虚函数表，本题关闭了标准 C++ RTTI（/GR-），所以 IDA 的 Class Informer 无法自动恢复类。但 MFC 自有的 CRuntimeClass 机制仍然保留，这是本题的突破口

MFC 逆向的 RTTI 恢复，就是利用 MFC 自有的 CRuntimeClass 链表及其 m_lpszClassName、m_pBaseClass、m_pfnCreateObject 等字段，从二进制中还原类名、继承关系、虚表和消息映射，把匿名结构还原成可读的 C++ 类模型

程序入口

IDA 反编译找到入口

MFC 程序里有个全局唯一的 App 对象，就是 CChallengeApp。整个程序从头到尾只有这一个实例，它代表 “这个应用程序本身”

Thread->InitInstance(Thread) 是虚调用，Thread 的实际类型是 CChallengeApp，所以这里会跳到 CChallengeApp::InitInstance

虚调用就是函数地址不写死在代码里，而是运行时根据对象的实际类型去查虚函数表（vtable），决定调哪个版本——所以 Thread 实际是 CChallengeApp，就调 CChallengeApp::InitInstance，而不是基类的 CWinThread::InitInstance

CWinApp::InitInstance(this); 是 MFC 基类初始化的，直接看 DecryptAllClassNames

第一步：取主链头

MFC 在 CRT 初始化阶段，通过 AFX_CLASSINIT 把所有 CRuntimeClass 静态实例自动挂进这条链。所以程序启动后，链上已经有所有注册过的类

  • AfxGetModuleState() 返回当前 MFC 模块态；

  • m_classList.m_pHead 是 CRuntimeClass 全局链表的头指针；

  • 沿 m_pNextClass 一直走，上限 4096 防死循环

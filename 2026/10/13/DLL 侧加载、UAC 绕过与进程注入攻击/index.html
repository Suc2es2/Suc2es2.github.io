DLL 侧加载、UAC 绕过与进程注入攻击

样本信息

  • 输入文件：sideloading_uacbypass_rundll32_injection_c2.evtx

  • 来源：Microsoft-Windows-Sysmon/Operational

  • 事件总数：18 条

  • 事件分布：Event ID 1 × 7；Event ID 7 × 6；Event ID 8 × 3；Event ID 11 × 2

  • 主机：MSEDGEWIN10

  • 用户：MSEDGEWIN10\IEUser

  • 事件发生时段（UtcTime）：2020-10-17 11:43:27.491 至 11:43:49.217 UTC（北京时间 19:43:27 至 19:43:49）

  • 注意：Record 18 的 EVTX 记录头写入时间为 0（显示为 1601 起点），但事件内部 UtcTime 是 2020-10-17 11:43:49.217，时间排序优先采用 UtcTime

攻击链

DLL 侧加载与软件伪装

日志显示 DLL 有有效签名且签名主体为韩文名称

UAC 绕过

CLSID {3E5FC7F9-9A51-4367-9063-A120244FBEC7} 对应 CMSTPLUA COM 对象，公开安全研究与检测规则将这个父子进程模式识别为典型 UAC 绕过线索

程序落地和再次侧加载

远程线程创建

三条 Sysmon Event ID 8：

Record ID 源进程 目标进程 NewThreadId StartAddress
13 WINWORD.exe PID 2920 PID 840，<unknown process>（可以关联 Record 12 的 rundll32.exe PID 840） 3608 0x0000000002FF0000
15 WINWORD.exe PID 2920 explorer.exe PID 6552 7872 0x0000000000930000
17 WINWORD.exe PID 2920 WINWORD.exe PID 1576 7068 0x0000000000960000

这些日志证明出现了跨进程远程线程创建

Rundll32 / Explorer 由异常进程启动

命令行没有典型的 DLL,Export 参数，因此可以证实该系统工具参与进程链，但不能由此推断它通过命令行执行了指定 DLL 导出函数

尝试痕迹清理

命令意图似乎是稍作延迟后删除 DLL

WSUS 伪装程序跨浏览器读取凭据数据库

样本信息

  • 原始文件：CA_chrome_firefox_opera_4663.evtx

  • SHA-256：e23b74c463d1fba5c1ef44bcc5f386c56a17327a5b216118f6704cc30545cd8c

  • 文件大小：69,632 字节（68 KiB）

  • 日志类型：Windows EVTX / Security 安全事件日志

  • 日志主机：IEWIN7。

  • 有效物理记录：5 条（裁剪文件物理 Record ID 1—5）

  • 原始事件 XML 的 EventRecordID：4987—4991；与裁剪后物理编号不同

  • 事件分布：Event ID 1102 × 1（安全日志已被清除）；Event ID 4663 × 4（文件对象访问）

  • 事件提供程序：1102 来自 Microsoft-Windows-Eventlog；4663 来自 Microsoft-Windows-Security-Auditing

  • 取证时间范围（UTC / XML SystemTime）：2019-04-27 19:27:55.274060 — 2019-04-27 19:33:50.134293

  • 北京时间（UTC+8）：2019-04-28 03:27:55.274060 — 2019-04-28 03:33:50.134293

  • 行为账户：IEWIN7\IEUser，SubjectLogonId=0xffa8

  • 可疑读取进程：C:\Users\Defau1t\wsus.exe，ProcessId=0x134c（十进制 4940）

  • 文件访问权限：AccessMask=0x1，AccessList=%%4416，含义为文件的 ReadData（读取文件数据）

攻击链

Security 审计日志被清除

读取 Opera 密码数据库（Record 2 / Event ID 4663）

访问目标是 Opera Stable 用户资料中的 Login Data，而访问者不是 opera.exe，而是名为 wsus.exe 的另一进程。

读取 Firefox 密钥数据库（Record 3 / Event ID 4663）

key4.db 是 Firefox 配置文件中与加密凭据/密钥材料有关的数据库，单独访问这一文件便值得调查，但真正重要的是它与下一条 logins.json 位于同一个 Firefox Profile

读取 Firefox 登录数据（Record 4 / Event ID 4663）

key4.db 与 logins.json 在同一个 kushu3sd.default Profile 中被同一 PID 连续读取，间隔约 13.392 秒

Firefox 的这两个文件配合用于保存和管理加密的登录信息，因此这种成对访问比随机读取一份普通配置文件更有明显的凭据获取指向

读取 Chrome 登录数据库（Record 5 / Event ID 4663）

Login Data 是 Chrome/Chromium 体系常见的用户登录凭据存储数据库路径

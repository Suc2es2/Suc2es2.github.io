Hide and Seek IoT Botnet 流量分析

通信环境

本次分析的流量属于 Hide and Seek（HNS）IoT 僵尸网络活动。受感染主机为 192.168.100.103，运行于 Raspberry Pi 3+ / Raspbian 环境

攻击链

初始感染与恶意程序运行

攻击链的起点是 192.168.100.103 已经被恶意程序控制

P2P 节点发现

这是本次流量中最明显的行为之一

项目 内容
本地主机 192.168.100.103
本地 UDP 端口 43763
传输协议 UDP
目的地址 随机外部 IP
目的端口 随机 UDP 端口
报文数量 约 39.96 万

在整个捕获文件中，没有发现发往本地主机 UDP 43763 端口的对应 P2P 响应

P2P 在这里的作用是让感染主机通过 UDP 向大量随机地址探测并交换节点信息，从而在没有单一中心 C&C 服务器的情况下寻找其他受感染节点、维持去中心化通信网络

互联网设备扫描

在 P2P 搜索进行的同时，192.168.100.103 开始向大量外部地址发送 TCP SYN 报文

发现的主要目的端口如下：

目的端口 SYN 数量 不同目标 IP
TCP 23 448,998 91,351
TCP 2323 146,546 30,364
TCP 9527 73,803 15,314
TCP 8080 223,264 45,484

四个端口合计发送约 892,611 个 SYN 报文，涉及 182,510 个不同目标 IP

其中，TCP 23 和 TCP 2323 合计涉及 121,714 个不同目标 IP

扫描目的：

  • TCP 23：寻找标准 Telnet 服务

  • TCP 2323：寻找使用非标准端口提供 Telnet 服务的设备

  • TCP 9527：探测额外的 IoT 管理服务

  • TCP 8080：寻找 HTTP 管理页面及可能存在漏洞的设备

Telnet 弱口令攻击

在发现开放 Telnet 服务的目标后，恶意程序进一步尝试使用预设的用户名和密码组合进行登录

这一行为是本次攻击链中最重要的传播环节

HTTP 服务识别

除了 Telnet，恶意程序还会扫描 HTTP 管理服务

本次捕获中共发现 3,314 条不同 TCP 流中的 HTTP 请求

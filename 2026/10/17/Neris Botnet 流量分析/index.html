Neris Botnet 流量分析

通信环境

本次分析的样本为 Neris Botnet 网络流量捕获文件。通过对 PCAP 文件进行解析，发现其中存在大量异常网络通信，涉及 HTTP、DNS、SMTP、SOCKS5 以及自定义二进制通信协议

样本中最值得关注的内部主机为：147.32.84.165

攻击链

恶意文件下载

在 09:06:36 UTC 左右，主机开始从多个外部服务器下载文件

对 HTTP 响应正文进行提取，并检查文件头，发现多个文件的真实类型与扩展名不符，文件头均能识别出 Windows PE 格式特征

从 HTTP 响应正文中恢复了 16 个 PE 文件实例，按 SHA-256 去重后得到 12 个不同样本，其中多个文件采用 UPX 压缩

这说明主机并非单纯下载普通网页资源，而是在获取多个 Windows 可执行程序或程序组件

恶意程序执行与持久化能力

在下载的 PE 文件中，选择 gggg_r.jpg 作为重点分析对象

恶意文件包含服务创建、注册表操作和文件释放相关功能，具有实现 Windows 服务持久化的能力

C2 注册与周期性状态上报

在 09:08:49 UTC，感染主机首次向以下服务器发送 HTTP POST

其中 os=2600 与 Windows XP 内核版本号相符

累计请求了 53 次，这说明感染主机持续向 C2 报告自身状态，并接收服务端响应

C2 节点发现与代理入口获取

继续分析感染主机与外部节点之间的 TCP 6667 通信

虽然 6667 通常与 IRC 协议相关，但本样本中发现的是 HTTP POST 请求

经过统计：

  • 19 个不同的远端 IP 地址参与 TCP 6667 通信

  • 发现 31 次能够提取 CB2 地址的响应

  • 31 次响应全部指向同一个端点

这一机制表现为：

  • 感染主机向多个外部节点发送自定义 HTTP POST

  • 请求携带 CB2: 1 标记

  • 部分节点返回统一的 CB2 地址

  • 感染主机随后连接该地址

反向 SOCKS5 代理建立

感染主机与 212.117.171.138:65500 建立 TCP 连接

需要注意，这条连接由感染主机主动建立，但后续 SOCKS5 请求由远端通过该连接发送

目标地址 端口 成功 CONNECT 数
smtp.aol.com 587 62
login.live.com 443 9
smtp.mail.yahoo.com 587 2
其他邮件及 HTTPS 服务 多种 多个

合计识别到 158 条符合 SOCKS5 CONNECT 结构的请求记录，其中 90 条存在成功状态响应

这里的感染主机实际上承担了反向 SOCKS5 代理节点的角色，远端控制者可以借助感染主机的网络连接访问其他服务

SMTP 垃圾邮件发送

感染主机与多个外部 SMTP 服务器建立连接，主要使用 TCP 587 端口

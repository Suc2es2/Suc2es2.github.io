Android HawkShaw 流量分析

通信环境

HawkShaw 是一种 Android 远程访问木马（Remote Access Trojan，RAT），采用云端控制架构，通过 Firebase 平台实现受害设备与控制端之间的通信和数据交换

本次实验使用 Nokia 6.1 手机，运行 Android 10，受害设备 IP 为 10.8.0.249，控制端对应的 Firebase 服务 IP 为 35.201.97.85

攻击链

恶意程序初始化与 Firebase 注册

恶意程序启动后，首先需要向 Firebase 注册当前应用实例，Firebase 是 Google 提供的一套云端应用开发平台

正常开发者可以利用 Firebase 实现：

  • 用户认证

  • 数据库存储

  • 消息推送

  • 文件上传和下载

  • 应用实例管理

  • 应用运行数据统计

HawkShaw 利用了其中的一些服务

本次分析主要涉及三个部分：

  • Firebase Installations
    负责应用实例的注册和标识管理，可以为应用实例提供唯一标识及认证令牌

  • Firebase Realtime Database
    实时数据库，可以在应用和云端之间同步数据。
    在本次样本中，firebaseio.com 域名对应的通信承担了 HawkShaw 控制服务的重要通信功能

  • Firebase Storage
    云端文件存储服务，主要用于保存照片、视频、音频、文档等文件

这三个服务可以形成一套完整的通信体系：

这里最值得注意的是：

Firebase 本身是合法的云服务平台。真正具有恶意性质的是 HawkShaw 利用这些服务执行远程控制和信息窃取的行为

发现关键域名：firebaseinstallations.googleapis.com

Firebase Installations Service，简称 FIS，它的主要作用是管理应用实例

可以这样理解：

  • 假设有一款应用安装在一百万部手机上

  • Firebase 需要知道：

    • 哪一个应用实例正在访问服务

    • 当前请求属于哪个应用实例

    • 如何为应用实例分配对应的认证信息

因此，Firebase Installations 可以为应用实例提供唯一标识（Installation ID）和认证令牌（Auth Token）

这两个信息可以帮助恶意程序完成后续 Firebase 服务通信

建立 C2 命令与控制通道

先建立 TCP 请求，TLS 负责在这条连接上建立加密通信

为什么 IP 没有变化，域名却变化了？

因为 Firebase 是云端服务平台，可能根据其内部的路由和负载分配策略，将请求分配到不同的服务节点

传统 RAT 可能采用这样的通信方式

HawkShaw 则采用了不同的架构

数据收集与文件外传

Exfiltration 是数据外传，通常指攻击者将受害设备中的数据传输到外部服务器

这里需要区分两个动作：

  • Collection：从设备中收集数据

  • Exfiltration：把收集到的数据发送到外部

在 PCAP 中发现三条访问 firebasestorage.googleapis.com，这个域名对应 Firebase Storage 服务

Firebase Storage 是云端文件存储服务，可以用于上传和下载较大的二进制文件

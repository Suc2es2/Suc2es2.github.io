假字体更新诱导的 Monero 挖矿木马流量分析

通信环境

样本链接：https://malware-traffic-analysis.net/2017/11/27/2017-11-27-Monero-coinminer-from-fake-font-update-2-pcaps.zip

本次样本有两个流量包，先看 Chrome 的

攻击链

浏览器访问主页

过滤 HTTP 请求

页面最底部有这一段

变量开头是 data:image/jpg;base64,，看起来像一张 base64 图片，但实际后面并不是 base64 图片数据，而是十六进制密文。这是典型的混淆伪装

密钥藏在字符串索引 22~23

索引 22、23 对应字符是 d2，循环从索引 24 开始，每两位十六进制解码

解码后拿到代码

简要行为：

  • 使用 left:-100% 把内容移出屏幕隐藏；

  • 检查 document.referrer，判断是否从外部站点进入；

  • 非 Windows 环境跳转到 http://div-class-container.ru/index5.php；

  • Windows 下的 Chrome/Firefox 通过 Cookie 计数，注入 https://laccrochecoeur.shop/.../index.php?m=f 脚本；

  • 排除了 .edu、.gov、.mil 域名

伪造字体更新

原始 Malware-Traffic-Analysis 研究证实，这是一场将网站访问者引至假 Tungsten Rounded 字体更新的社会工程学攻击

  • Chrome：通过 ?m=z 交付 ttf.zip，其中包含 ttf.js；

  • Firefox：通过 ?m=j 直接交付 ttf.js；

  • 后续由脚本触发 ?m=e 交付 Monero 挖矿程序；

  • ?m=f 对应伪造字体缺失/更新提示脚本

恶意脚本投递

查询 laccrochecoeur.shop 的 IP 地址

随后则与 laccrochecoeur.shop 进行了加密通信

根据原始案例，该服务器通过伪造字体缺失提示，诱导 Chrome 用户下载 ttf.zip，Firefox 用户下载 ttf.js，进而执行恶意脚本并下载挖矿程序

需要注意，这部分 HTTP 请求发生在 TLS 加密通道内，当前 PCAP 无法直接还原下载路径和文件内容，因此字体更新提示及具体文件投递方式需要结合原始案例佐证

矿池连接

过滤 DNS 协议发现第 2702 帧 A 查询 cdn192.168.0.11.pridnestrovie.m234.xyz

第 2703 帧 DNS 响应 185.202.103.26

开始发送 JSON-RPC 挖矿应用层数据，Agent 明确为 XMRig/2.3.1 (Windows NT 6.1)

login 是长钱包标识；agent 显示 XMRig/2.3.1 客户端；pass 为 x

服务器的成功响应包含 job 对象、blob、job_id、target 和 status: OK。其中 blob 为工作数据，target 为目标难度表示

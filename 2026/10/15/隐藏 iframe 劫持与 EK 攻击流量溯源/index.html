隐藏 iframe 劫持与 EK 攻击流量分析

通信环境

样本链接：https://malware-traffic-analysis.net/2014/11/08/index2.html

打开 Wireshark 后，先查看 Statistics → Protocol Hierarchy 与 Statistics → Conversations → IPv4

确认抓包中哪些内网主机与哪些服务器通信，这里能看到不止一台内网客户端，包括 172.16.165.132、172.16.165.133 和 172.16.165.159

攻击链

感染主机

流量包中有 HTTP 请求，先看 172.16.165.159 的 HTTP 请求

发现大多数都是图片以及 CSS 等静态文件

在 “统计 –> 会话” 中勾选 “显示过滤器的限制”

172.16.165.159 可以排除，因为字节数太少了

有一组 300 多字节的流量，追踪一下没发现异常

172.16.165.132 对 91.146.108.148 通信分组特别多

看了一下全是图片，可以先排除掉

最后只剩 172.16.165.133 了，其对 173.254.80.53 通信非常多

过滤一下

恶意 iframe

追踪第一个 JS 文件

这段代码含义是读取 cookie，检测 User-Agent，在特定条件下向页面写入一个隐藏 iframe，加载 http://genfaglobal.ga/lissyanger17.html，并设置 48 小时 cookie

这是高度可疑的隐藏 iframe 注入代码，可能用于广告、跟踪、流量劫持或恶意内容加载

原本主机要访问的域名是 www.kentroxarisma.com，但是 JS 代码恶意加载了 genfaglobal.ga

恶意 302 重定向

过滤一下有关这个域名的流量包

追踪数据流，这里直接 302 跳转到了 http://seedradrivergy.co.vu/411c0ce8fafz_1_08282d03fb0251bbd75ff6dc6e317bd9.html

EK 落地

继续追踪

追踪第一个流量包发现内部存在大量混淆的 JavaScript、无规律变量名和动态函数构建痕迹

这里要强调：落地页是通过 HTTP Chunked（分块传输编码）下发的。 Wireshark/脚本分析时要先重组 TCP，再还原 HTTP 分块内容。不能拿 TCP Len 或某个分片的长度当作完整 HTML 文件大小

打开导出对象可以看到传输的恶意文件，其中一个文件连续下发了三次

导出后放到云沙箱识别为木马

后续并未发现受害主机有横向的流量

G01PACK EK 投递锁屏型勒索软件流量溯源

通信环境

样本链接：https://malware-traffic-analysis.net/2013/08/23/2013-08-23-g01pack-EK-traffic.pcap.zip

在 “统计 –> 会话” 确认受害主机只有一台

攻击链

恶意 302 重定向

看到 HTTP 优先过滤掉

首先第一个请求就是 302 重定向，但是原本域名是 mpraid3.com，却跳转到了 kucf.3wasnev.info

明显不是正常请求

Java 利用组件

把和这个域名相关的请求全部过滤出来

追踪第一段请求的 HTTP 流

这段 HTML 是一个典型的多插件挂马/漏洞利用页面，通过同时嵌入 Java Applet、Java Web Start 和 Flash 三类旧式浏览器插件，试图在访问者机器上加载远程载荷

Java Applet 嵌入

  • classid:8AD9C840-044E-11D1-B3E9-00805F499D93 是 Java Plug-in 的 CLSID

  • code="r" 表示要加载的 Java Applet 主类名为 r

  • archive 指向远程 .jar 文件

  • codebase 指定远程基础路径

作用：让浏览器通过 Java 插件下载并运行远程 JAR，可能利用旧版 Java 漏洞

Java Web Start 嵌入

  • classid:5852F5ED-8BF4-11D4-A245-0080C6F74284 是 Java Web Start 的 CLSID

  • app 指向 .jnlp 文件

作用：触发 Java Web Start 下载并启动远程 Java 应用，同样可能被用于投递恶意程序

Flash 嵌入

  • classid:d27cdb6e-ae6d-11cf-96b8-444553540000 是 Shockwave Flash 控件

  • movie / embed src 指向远程 .swf

  • allowScriptAccess="always" 允许 Flash 与页面 JavaScript 交互，风险较高

  • 宽高只有 10x10，属于隐藏式加载，用户几乎看不到

作用：加载远程 Flash 内容，可能利用旧版 Flash 漏洞

来自网络请求的客户端 UA 标示 javaws/1.6.0_25、Java/1.6.0_25。此版本较老，符合历史客户端漏洞利用的受众，但仅凭 JAR 名称/Java 版本无法精确归因到某个 CVE

后续传输了四次恶意的 JAR

XOR 混淆的两种 PE 载荷

最重要的异常内容来自 GET /6c2c7b0be76e03a583fc65dc488fdbff/0 和 /4，尽管 HTTP 响应将其标成 text/html，但正文根本不是 HTML，而是经过单字节 XOR 的 PE 可执行文件

静态还原后前几个字节的规律如下：

特别注意开头是 00 4D 5A，也就是一个 00 字节后才出现 MZ

两组不同的密钥还原为相同 SHA256，因此共获取了 2 个唯一 PE 载荷

下载可疑二进制资源

在后续通信中，感染主机向 rightclickcoast.info 发送两次 GET 请求

追踪数据流发现不是正常的 HTML 以及 PHP 文件，更像是压缩过的二进制文件

两条复用的 TCP 连接随后分别提交 PUT 请求，追踪数据流发现其中一个是图片

复制原始数据下载下来

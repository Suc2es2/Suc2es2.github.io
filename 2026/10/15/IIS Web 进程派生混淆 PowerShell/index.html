IIS Web 进程派生混淆 PowerShell

样本信息

  • 原始文件：discovery_sysmon_1_iis_pwd_and_config_discovery_appcmd.evtx

  • SHA-256：5388d3281a902a1f3cc087697589145b7de6abdbbc0dc716abd6a702c44bb106

  • 文件大小：1,118,208 字节（约 1.07 MiB）

  • 有效 EVTX 记录：40 条，Record ID 1—40。

  • 事件提供程序与通道：Microsoft-Windows-Sysmon / Microsoft-Windows-Sysmon/Operational

  • 事件类型：Sysmon Event ID 1 — Process Create（进程创建），共 40 条

  • 主机：IEWIN7；行为账户：IIS APPPOOL\DefaultAppPool

  • 主要时间区间（EventData.UtcTime，UTC）：2019-05-27 01:28:42.700 — 2019-05-27 01:29:20.475

  • 共同登录会话：LogonGuid={365abb72-b26b-5cea-0000-002023240800}，LogonId=0x82423

**进程派生（Process Spawning）**是指一个正在运行的进程（父进程）创建并启动另一个新进程（子进程）的行为，例如 IIS 的 w3wp.exe 启动 powershell.exe，后者再启动 appcmd.exe

攻击链

IIS 工作进程派生高完整性级别 PowerShell

IIS 工作进程 w3wp.exe（PID 748，应用程序池 DefaultAppPool）启动 PowerShell（PID 2584），并使用 -nop -noni -enc 参数执行编码命令

-nop 表示不加载 PowerShell Profile；-noni 表示非交互运行；-enc 是使用 UTF-16LE Base64 编码命令

解码 PowerShell 命令，发现 XOR 解码与内存执行

原始 CommandLine 中的 -enc 后是 Base64；将其作为文本数据进行离线解码，可恢复 PowerShell 脚本

以下摘录了对案件判断有意义的语句

分析要点：

  1. 使用 ReadAllBytes 读取两个位于 C:\Windows\Temp\6jrxk3\ 的无扩展名文件：gfg9i 和 nja9t64rrlu8

  2. 对每个文件使用 -bxor 和循环密钥执行逐字节 XOR 解码，再按 UTF-8 转为字符串。原脚本的密钥用 UTF8.GetBytes(...) 转换，并非直接把十六进制字符串解析成二进制密钥

  3. 使用 ($dec_module+$dec_app_code) | iex 在当前 PowerShell 中解释执行拼接后的脚本文本，属于内存中执行的迹象

  4. 随后尝试使用 Remove-Item -Force 删除 nja9t64rrlu8，该语句本身不能证明删除成功

连续查询应用程序池用户名和密码

Record ID 4—21，共 18 条：

  • Record 7 / PID 2928： "C:\Windows\System32\inetsrv\appcmd.exe" list apppool /text:processmodel.password

  • Record 10 / PID 3444： "C:\Windows\System32\inetsrv\appcmd.exe" list apppool /text:processmodel.username

  • Record 11 / PID 560： "C:\Windows\System32\inetsrv\appcmd.exe" list apppool /text:processmodel.password

  • Record 16 / PID 3144： "C:\Windows\System32\inetsrv\appcmd.exe" list apppool "Description: Cannot read configuration file due to insufficient permissions" /text:processmodel.username

  • Record 17 / PID 3100： "C:\Windows\System32\inetsrv\appcmd.exe" list apppool "Description: Cannot read configuration file due to insufficient permissions" /text:processmodel.password

其中 /text:processmodel.username 对应应用程序池进程运行账户，/text:processmodel.password 对应其配置密码字段（具体是否配置及是否可读取取决于身份类型、配置和权限）

测验

# 问题 答案
1 样本包含几条有效事件？ 40 条。
2 日志来自哪个通道？ Microsoft-Windows-Sysmon/Operational。
3 主要事件 ID？ Sysmon Event ID 1（Process Create）。
4 主机名？ IEWIN7。
5 主要执行身份？ IIS APPPOOL\DefaultAppPool。
6 初始可疑父进程是什么？ w3wp.exe。
7 w3wp.exe PID？ 748。
8 PowerShell PID？ 2584。
9 PowerShell ProcessGuid？ {365abb72-3d4a-5ceb-0000-0010fa93fd00}
10 AppCmd 进程一共多少条？ 39 条。
11 AppCmd 的共同父进程 PID？ 2584。
12 全部事件共享的 Logon ID？ 0x82423
13 主要进程完整性级别？ High。
14 PowerShell 命令行有哪些特殊参数？ -nop、-noni、-enc。
15 PowerShell -enc 采用什么字符编码？ 这里用 UTF-16LE Base64。
16 PowerShell 的外部文件读取函数？ [System.IO.File]::ReadAllBytes。
17 PowerShell 用什么方法解码文件？ 逐字节 XOR（-bxor），配合循环密钥。
18 解码后的脚本如何被执行？ 拼接字符串后通过 iex（Invoke-Expression）执行。
19 脚本试图删除哪个文件？ C:\Windows\Temp\6jrxk3\nja9t64rrlu8
20 发现虚拟目录实际路径的参数？ list vdir /text:physicalpath。
21 枚举应用程序池名称的参数？ list apppools /text:name。
22 查询应用程序池用户名的参数？ list apppool /text:processmodel.username。
23 查询应用程序池密码字段的参数？ list apppool /text:processmodel.password。
24 查询虚拟目录用户名的参数？ list vdir /text:userName。
25 查询虚拟目录密码字段的参数？ list vdir /text:password。
26 密码字段相关的 appcmd 调用有多少？ 18 条（各 9 条 AppPool / VDir）。
27 哪条记录首次查询应用程序池密码字段？ Record ID 5。
28 哪条记录首次查询虚拟目录密码字段？ Record ID 24。
29 后续列举时出现的 redirection.config 是什么？ 看起来是配置读取错误文本被当作对象名传入命令，不能证明存在该名称的应用程序池或目录。
30 出现 “Cannot read configuration file due to insufficient permissions” 意味着什么？ 它是命令行参数里出现的错误文本，暗示前面可能出现配置访问拒绝，但需实际输出/配置日志验证。
31 AppCmd 是否一定成功列出了凭据？ 否，进程创建事件没有命令 stdout 和返回码。
32 目前能否证明存在 WebShell？ 不能，只能证明 IIS 工作进程派生了编码 PowerShell。
33 能否还原 XOR 解码后的全部真实脚本？ 不能，缺少 C:\Windows\Temp\6jrxk3 中的两个输入文件。
34 攻击者 IP 能从本份日志得出吗？ 不能，日志没有 HTTP 请求或网络连接事件。
35 本日志最值得检测的进程链？ w3wp.exe → powershell.exe → appcmd.exe。
36 主要 ATT&CK 执行技术？ T1059.001（PowerShell）。
37 潜在凭据访问技术？ T1552.001（Credentials In Files），仅能作为疑似映射。

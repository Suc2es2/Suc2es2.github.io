攻击链

同一客户端连续尝试 sa 与 root

有人向 SQL Server 以 sa 登录名提交凭据，但服务端判定密码不匹配

sa 是 SQL Server 中具有特殊意义的内置高权限登录名

root 常见于其他平台或应用的管理员账户命名，但并非 SQL Server 内置 sa 的别名

六个 ##MS_*Certificate## 登录名

以下全部命中同一条失败原因：

Record 登录名 时间（UTC）
2 ##MS_SQLResourceSigningCertificate## 13:46:01.187637
3 ##MS_SQLReplicationSigningCertificate## 13:46:01.202731
4 ##MS_SQLAuthenticatorCertificate## 13:46:01.202731
5 ##MS_PolicySigningCertificate## 13:46:01.222452
6 ##MS_SmoExtendedSigningCertificate## 13:46:01.233944
9 ##MS_AgentSigningCertificate## 13:46:01.266435

这类 ##MS_*Certificate## 名称与 SQL Server 内部组件及证书用途相关

两个 ##MS_Policy*Login## 密码评估错误

这条消息表达的是“评估密码时发生错误”，并不等于“密码策略被破解”“密码正确”“密码复杂度不足”或“账户成功验证”

Record 登录名 原始失败原因
7 ##MS_PolicyEventProcessingLogin## An error occurred while evaluating the password.
8 ##MS_PolicyTsqlExecutionLogin## An error occurred while evaluating the password.

SQL Server 18456 登录失败事件分析问答

问题 回答
事件来源是什么？ MSSQLSERVER。
日志通道是什么？ Application。
事件编号？ 18456。
18456 表示什么？ SQL Server 登录失败。
目标主机？ MSEDGEWIN10。
来源 IP？ 10.0.2.17。
共有多少有效事件？ 10 条。
物理 Record ID？ 1—10。
原始 EventRecordID 范围？ 13026—13035。
涉及多少个不同登录名？ 10 个。
有哪些典型高价值账户名？ sa、root。
sa 登录成功了吗？ 未成功，日志显示密码不匹配。
root 登录成功了吗？ 未成功，日志显示密码不匹配。
root 是 SQL Server 默认超级用户吗？ 不是，不能与 sa 等同。
密码不匹配多少次？ 2 次。
身份验证方式不匹配多少次？ 6 次。
密码评估错误多少次？ 2 次。
6 个名称有哪些共同特征？ 含 ##MS_ 与 Certificate##。
##MS_*Certificate## 是否证明证书被窃取？ 否，只是失败登录名。
两个 Policy 登录名是什么？ ##MS_PolicyEventProcessingLogin## 和 ##MS_PolicyTsqlExecutionLogin##。
失败是否来自多个源 IP？ 否，均来自 10.0.2.17。
能确认账号喷洒使用同一个密码吗？ 不能，日志没有提供尝试的密码。
能确认 SQL Server 登录爆破成功吗？ 不能，只有失败事件。
可疑行为为何偏向自动化？ 10 个不同登录名在约 0.108 秒内密集失败。
能确定目标 SQL 端口为 1433 吗？ 不能，事件没有 TCP 目标端口。
能确认应用使用了 master 数据库吗？ 事件数据含 master，但不能据此确认任何成功数据库操作。
SQL 18456 与 Security 4625 一样吗？ 不一样，18456 来自 SQL 引擎，4625 来自 Windows 安全审计。
State 8 是否在这份 EVTX 中明示？ 没有；只是微软文档中密码错误的常见状态参考。
如何查看更详细 SQL 登录失败状态？ 关联 SQL Server ERRORLOG 中的 18456 State。
最稳妥的结论是什么？ 同一客户端短时批量触发 SQL 登录失败，疑似自动化用户名探测及密码猜测。

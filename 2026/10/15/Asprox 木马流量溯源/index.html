Asprox 木马流量溯源

通信环境

样本链接：https://malware-traffic-analysis.net/2014/12/11/2014-12-11-traffic-by-malware-from-Asprox-malspam-run-on-a-VM.pcap.zip

受害主机只有一台

攻击链

ZIP 木马下载

过滤 HTTP

追踪第一个数据包流发现下载了一个压缩文件

导出后放到云沙箱识别出是木马，家族类型 Kuluoz

木马回连

继续追踪下一个数据流，HTTP 正文为不可读二进制，尽管请求声称 application/x-www-form-urlencoded

响应 HTTP/1.1 200 OK，响应体 111,982 B，内容起始为 80 00 00 00，该行为不符合正常浏览器提交普通表单的典型模式

PE 与伪装 DLL 资源

继续往下追踪，/datamousthoping/mod_smartslider2/ 的响应虽然为空

但看完整的 TCP 流发现采用的是 chunked 分块传输。必须先 TCP 重组，再解 HTTP Chunked 数据，不得把单个 TCP 分段长度当成文件长度

改为追踪 TCP 流即可

复制响应部分的全部原始数据，去 CyberChef 上解密下载文件

云沙箱识别出为 Zbot 类型木马

后续又传输了一个 DLL 文件，可能是木马相关的配置

多节点 C2 通信

在 linktohttps.com、195.245.194.102:8080、70.32.94.46:8080 上，出现相似 HTTP URI 模式

多目标 IP、相似 URI、重复通信、失败重试共同支持已存在程序化控制行为

恶意 302 跳转

HTTP 流量的最后则是 302 跳转

国内某游戏大厂渗透测试

前言

本次测试属于公益类型的 SRC

弱口令

密保找回逐题可爆破 + 免旧密码重置导致真实账号被接管

来到忘记密码页面

匿名枚举可能存在的账号，经过测试发现 anquan 账号

爆破密码总结出规律

answer1 answer2 返回 code msg
错误值 任意/缺省 -2 密保问题 1 答案错误
xxx 缺省 -1 密保问题 2 答案错误
xxx 错误值 -1 密保问题 2 答案错误
错误值 xxx -2 密保问题 1 答案错误
xxx xxx 0 密保问题验证通过

成功进入设置新密码界面

URL 重定向

人脸核验中间页 ext1 参数开放重定向

人脸核验中间页在 pagetype=kf_mobile 时，把 URL 参数 ext1 直接作为 “返回账号修复” 按钮的跳转目标

前端只校验该值是否以 http://、https:// 或 // 开头，不校验目标域名是否属于白名单域名

核验初始化失败或成功后页面都会渲染该按钮，点击即执行 window.location.href = ext1 + return_info=error|success，可将用户从真实的域名页面跳转到任意外部站点，用于钓鱼

XSS

VIP SDK 活动页 DOM XSS

VIP SPA 的活动页 /vip/sdk/act 把 URL 里 backurl 参数的值直接拼进 window.location.href，没有任何协议白名单，只要用户点一下页面左上角的返回箭头，javascript: 伪协议就在源内执行任意脚本 —— 而且这个参数可以塞在 # 后的 fragment 里，服务端和 WAF 完全看不到

未授权访问

天机 BI 后台数据导出

正常情况下，天机 BI 平台应该先登录，再按账号权限只给我看自己业务线、部门或游戏的数据

但 quickBi-importData&a=list 这个 action 没有做登录校验，更严重的是，这个列表没有分页或行数上限。一次请求就吐出 33.9 MB

这就像公司财务后台的 “导出全表” 按钮没有上锁：任何人点一下就能下载全公司报表。这次只下到一半，但已经包含公司级财务、买量、组织和游戏明细

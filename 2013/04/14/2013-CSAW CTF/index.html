这里有三个关键问题：

  1. a2 是有符号 16 位整数

  2. n 是无符号 32 位整数

  3. 长度检查没有正确处理特殊值 -1

首先是第一处

在 32 位 Linux 中

当输入 -1，其 16 位二进制表示为 0xFFFF，转换成 32 位无符号整数后为 0xFFFFFFFF，也就是 4294967295

这就是有符号数转换为无符号数时产生的问题

再看 if ( (a2 + 1) <= 0x400 ) 代码的汇编，发现是 jbe 指令，它表示无符号小于等于

当我们输入 -1 时

第三处是 v7 = recv(fd, buf, n, 0);，Linux 下的原型是

第三个参数 len 是 size_t，也就是无符号整数

我们前面已经得到 n = 0xFFFFFFFF，但是 buf 实际只有 1024 字节，这就产生了越界写入

本题开启了栈可执行，我们不需要通过 ROP 调用 mprotect() 来修改栈权限，可以直接把 Shellcode 放在栈上执行

因为栈地址受到 ASLR 影响。我们虽然能够控制 EIP，却不一定知道 Shellcode 在哪里

所以，ROP 在这道题中的主要用途是地址泄露，而不是绕过 NX

本题恰好有一个可以利用的函数：send(fd, buf, len, flags);，我们可以利用 ROP 让程序重新执行这条指令

send(fd, buf, len, flags) 在 32 位 cdecl 调用中，参数从栈顶开始依次排列：

如果直接跳到了 0x08048d04，也就是 call send@plt 这条指令本身

则跳过了前面 4 条 mov 指令，所以 send 的参数不会自动被设置好；那怎么办？

函数 08048EFE 被调用时，栈帧里本来就存着一些数据——局部变量、保存的寄存器、函数调用留下的返回地址、之前 recv 读入的缓冲区地址指针等等

这些数据的值是固定的，但它们的位置取决于 ESP 在哪里

每执行一个 ret 就从 ESP 取出一个值当作新 EIP，然后 ESP 移动 4 字节

当 EIP 到达 call send@plt 时，这些旧数据在 [esp]、[esp+4]、[esp+8]、[esp+12] 位置上，刚好能被 send 当作 fd、buf、len、flags 使用

文件描述符 4 正好是客户端的 Socket 连接

第二份 Payload：执行 Shellcode

它执行的命令是 /bin/bash 1>&4 0<&4，接下来按照第一部分的布局拼接

组成部分 长度 作用
b"A" * 1056 1056 字节 填满缓冲区，直到覆盖到函数的返回地址。
struct.pack("<I", 0xbffff64a) 4 字节 这是第一阶段泄露并计算出的真实栈地址，用来覆盖原函数的返回地址。程序执行完当前函数后，EIP 就会跳转到 0xbffff64a
b"\x90" * 20 20 字节 NOP 滑板。\x90 是空指令，CPU 执行到它会直接滑向下一条指令
shellcode 约 55 字节 恶意代码

为什么要放 20 个 NOP？

因为返回地址不必精确落在 Shellcode 第一个字节

只要落在 NOP 区域，CPU 就会连续执行 NOP，最后进入 Shellcode

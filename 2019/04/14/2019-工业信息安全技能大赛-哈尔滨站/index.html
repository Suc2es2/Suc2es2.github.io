2019 工业信息安全技能大赛-哈尔滨站 WriteUp

📝 赛事概况

  • 参赛规模：比赛共吸引了来自全国的 24 支队伍参加

  • 比赛项目：大赛设有 PLC 漏洞挖掘和 SCADA 漏洞挖掘两个比赛项目

🏛️ 组织架构

  • 指导单位：国家工业信息安全发展研究中心、黑龙江省工业和信息化厅

  • 主办单位：黑龙江省电子技术研究所、哈尔滨工程大学

🏆 比赛结果

  • 第一名：冀信安队

Misc

异常的 S7 数据（S7comm 协议）

大概看了一下，全是 0x05 功能码

绝大多数写入数据都以 ffff 开头

右键作为过滤器应用

WireShark 生成的语法是 s7comm.resp.data == ff:ff:96:e7:8f:51:c4:d0:3a:2b

我们更改为 s7comm.resp.data[0:2] != ff:ff，筛选出数据包

所以 flag 是 flag{FFAD28A0CE69DB34751F}

jadx 反编译 classes.dex

这段代码是一个 Android 加固脱壳的代理 Application，通过反射替换系统 Application 为真实的目标 Application 并调用其生命周期，同时加载 native 库执行初始化

在 onCreate() 方法中，代码大量使用 ReflectUtils 对 ActivityThread 和 LoadedApk 这些系统核心类进行反射操作：

  • 将 LoadedApk 中的 mApplication 设为 null，并从系统的 mAllApplications 列表中移除旧的 Application 对象

  • 强行将 ApplicationInfo 中的 className 修改为 "com.targetapk.MyApplication"

在系统感知之前，用真实的业务 Application 替换掉这个临时的代理入口

代码通过反射调用 LoadedApk.makeApplication 动态创建了一个新的 Application 实例，并将其赋值给系统的 mInitialApplication，最后直接调用了 app.onCreate()

这一步证明了该代理类的存在意义——它并不自己承担业务逻辑，而是充当 “启动器”，负责找到、构造并启动被加固保护的原始 Application，确保原始 App 的代码能够正常跑起来
